# 网页和产品界面去模板化

只在用户要求网页/UI设计、界面文案或去模板化时启用。本模式不允许以美化为由修改未授权业务逻辑、数据或依赖。

## 根据任务形成设计

先识别用户要完成的主要动作、信息类型、现有品牌、参考界面和技术栈。已有设计系统时沿用；无参考时提出一个适合内容的清晰方向，不必为所有风格问题反复询问。

- **层级：** 先安排核心内容、主操作和次要信息，再决定布局。不要无条件套“大标题Hero + 三张卡片 + 渐变按钮”。确实存在三个并列选项时可以使用三卡片。
- **配色：** 从品牌、内容、对比度和状态语义出发。紫色、纯色背景和默认色板并非错误；无理由复制流行组合才是问题。不要把所有页面改成另一套固定橙黑模板。
- **字体：** 优先可读性、中文覆盖、层级与现有栈。无需为了不同而替换常用字体或远程加载新字体。
- **组件：** 根据项目已有库调整间距、排版、密度和状态。不要为了“去AI味”擅自新增组件库、换框架或堆炫技动画。
- **文案：** 写清按钮做什么、状态是什么、下一步是什么。不得编造效率数字、客户Logo、用户头像、评价、资质或安全承诺。
- **图像：** 优先用户已有或明确许可的资产。功能图标须可辨识并有可访问名称；不强制从外站拉图，不以无授权图片冒充真实产品或客户。
- **动效：** 服务反馈和定位，尊重 reduced-motion；不要强制噪点、位移、弹簧或进场动画。

## 自检与交付

检查桌面与窄屏布局、键盘路径、可见焦点、颜色对比、图标名称、错误/空/加载状态及内容完整性。只报告实际做过的检查；没有运行或截图就不要声称“全部适配通过”。保持页面功能和原有测试，说明哪些改变是视觉/文案，哪些验证尚未执行。

没有获得文件修改授权时返回方案或代码片段，不自动安装依赖、访问外部图像服务、修改配置或重写整站。
