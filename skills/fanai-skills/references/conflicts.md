# 上游规则冲突的明确处理

原始规则已完整保留，不能把它们相互矛盾的命令直接叠加。以下是整合版的执行解释，不冒称所有原句均可同时无条件执行。保护事实、授权和必要披露优先；用户可决定文体与审美，但不能由此伪造结果。

| 上游差异/风险 | 整合版如何执行 | 验收项 |
| --- | --- | --- |
| 反防御性原文强调“不说输”“不主动示弱” | 删除空洞自我攻击，不隐藏影响结论的不利结果、局限和反例；有证据的负面比较如实写 | F03–F05、A03 |
| “更换比赛维度/重定义故事”与学术保真 | 只有获准重构时才提议调整，不能事后改分母、筛选结果或悄改研究问题 | F07、A01–A06 |
| 普通humanizer鼓励像聊天、有观点、我、情绪和跑题；学术humanizer要求学术语域 | 论文保留精确、中性、必要被动和we；普通内容匹配作者真声音，不造人设或故事 | A09/A12、W01 |
| academic-humanizer要求段落数相同，两个quick prompt要求最小修改/不整段重写；用户可能要求压缩/重构 | 先审计，普通润色保持作者措辞与结构，只改问题位置；明确授权压缩/重构时才可扩大修改，但不静默丢独立事实或关键引用 | F02、G02/G07 |
| 学术原版禁em-dash；通用版允许少量；数学/代码可能使用相似字符 | 学术正文默认改写装饰性em-dash；其他文体按功能和默认提示检查；公式负号、数值区间和命令不动 | A11、T12 |
| noai将一些高频词、列表、三项结构绝对禁止 | 对空泛、机械用法实施检查；专业词义、真实列举、引语和用户要求的格式保留，不按词判AI身份 | T01–T16 |
| noai要求“具体化”，示例出现节省小时数或个人经历 | 只有材料提供的数字、经历和身份可用；缺证据时直接解释功能，不照搬示例 | F01/F04、W05 |
| noai网页原文禁紫色/纯色/对称、强制噪点/指定组件库与外站图片 | 用于识别无理由的默认模板，不覆盖品牌、可访问性、现有栈和权限；不自动联网、上传或装库 | D01–D08 |
| 网页原文建议每句不超过15字 | 优先简短、清楚；不可截断安全提示、法律文字或操作条件 | F05、D06 |
| 泛化“可能”应精简；研究结果本来不确定 | 精简的是重复模糊，不删不同命题各自需要的限定，不将suggests改成proves | F03、A07/A09、T15 |
| 基金原文提及固定页数、Aim数量和前几页的重要性 | 作为一般写作经验；具体要求按当年官方征集文件核对，不伪称合规 | P02、P07 |
| noai的50分量表与“基本看不出AI痕迹” | 五维用于定位问题；评分主观，不是身份检测、盲测或无错认证，也不承诺固定通过率 | G05/G06 |
| 上游集成指南包含运行代码、安装扩展、下载图片或上传截图 | 作为归档资料；本次未授权时不执行其中命令，不发送私人材料 | F07/F08、D04/D05 |
| 上游Before/After示例可能新增证据，也可能把“超过300”改成“300”、把“可能影响”改成“会影响” | 只能学表达结构，不能推定After事实可从Before推出，也不能只看数字没变就判保真。数量限定、比较关系和确定性须人工对照；NSF的funded/permission声明不表示当前用户有同样经历或可逐句冒用 | F01/F03/F04、G02 |
| 上游资源概述将聚合图片/图标资源笼统写成MIT、免费或商用无需署名 | 归档保留，不背书现行外站授权、价格或API。使用时核对具体资产的许可和署名条件；合法图库照也不能冒充真实客户/团队 | D05 |
| 上游把ease-in-out误称为linear | ease-in-out本身不是线性缓动；是否采用由反馈目的、项目需求和可访问性决定，不按该误称判错 | D07 |
| 原文破折号上限出现≤2/≤3，词频上限出现≤3/>5等不一致 | 只作相应文体的复核提示，不当作必须同时满足的硬门槛，不为凑计数损坏真实内容 | T08/T12、G05 |
| 原型允许占位，成品应有真实内容 | 原型占位须有授权与明确标记，终稿逐项替换或标待确认；材料不足不编产品/团队照片、数据或评价 | D05/D09 |

遇到表中未覆盖的实质冲突时，指出冲突并完成可独立处理的部分；不暗自丢掉一方规则，不为了“全通过”伪造检查记录。
